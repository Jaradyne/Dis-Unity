## Architectural intent

Keep provider identity separate from role identity. Trees know *what kind of work is needed*; the dispatcher chooses from a contextual candidate set. A different model or sibling branch is not independent empirical evidence merely because it is different.

A node request should minimally carry:
- Question + epoch;
- tree + node + branch + inherited history;
- bounded task / reason for initiating work;
- evidence/source/API lineage visible to the operation;
- required output contract;
- permissions/budget;
- candidate-role constraints;
- stop/failure return path.

The candidate set should preserve **why** each option is present or absent. Examples:
- Language tree can elevate Parallax / multilingual-capable roles and known language-fit providers.
- Diplomacy can elevate official-surface comparison and cautious rhetorical-occlusion roles.
- Customs can elevate Customs Authority archetype / trade-flow collectors.
- Economics can elevate price/payment/cash-flow roles.
- Production can elevate physical throughput / operations evidence roles.
- A tree/location may also prefer deterministic/no-model work when that is enough.

Provider state should distinguish:
- eligible now;
- eligible but not needed;
- unavailable/quota/cooldown;
- requires first-use approval;
- prohibited;
- unknown/unverified.
